# 俱乐部入职文考网站

一个不依赖第三方 npm 包的 Node.js 网站，题库可从结构化 Word 文档导入。本项目使用 Node.js 原生 HTTP 服务，可直接在本机或云服务器运行。

## 交付说明

- 交付包：`jlb-entry-exam-project.zip`
- 默认端口：`3000`
- 默认所有者账号：`admin` / `admin123`（正式部署必须修改初始密码）
- 演示模式：通过环境变量 `DEMO_AUTO_PAY=1` 开启，付款申请会自动确认
- 正式模式：默认关闭演示模式，付款需要管理员在后台核对后手动确认

## 已实现

- 30 道随机试卷：单选 15、判断 6、简答 6、情景 3。
- 同一份试卷题目不重复，客观题自动判分，主观题按参考答案辅助评分。
- 85 分通过，仅通过后生成可查询、可打印的证明。
- 每位考生按个人考核次数付费，最多 6 次；首次免费，第二次 20 元，第三次起每次 30 元，考费全部归考官。
- 考生付款页固定展示项目内置的微信和支付宝收款码，由管理员核对到账后确认付款。
- 多管理员独立凭据与角色管理（所有者、系统管理员、考官、财务）。
- 题库新增、编辑、删除、答案设置、启停、分类筛选与组卷规则配置。
- 简答题和情景题支持 DeepSeek V4 Flash AI 评分，失败时自动回退本地评分要点算法。
- 待付款 30 分钟自动取消；固定收款码付款后支持管理员或财务人工确认。
- 后台可生成带有效期和使用次数的答题码，考生可免支付直接开考；可选是否按应收考试费计入收款统计。
- 运营总览展示累计/今日收款、付款笔数、考试与通过率、近 7 天趋势及渠道构成。
- 数据保存在本机 `data/state.json`，适合单机或小规模部署。

## 账号与入口

### 管理员账号

首次启动会创建所有者账号：

```text
管理员入口：http://localhost:3000/admin
用户名：admin
默认密码：admin123
```

正式启动时建议设置强密码：

```bash
ADMIN_PASSWORD='替换成你的强密码' node server.js
```

`ADMIN_PASSWORD` 只用于首次创建 `admin`。账号随后保存在 `data/admin-users.json`，密码使用随机盐和 scrypt 哈希保存。所有者可在后台创建多个独立管理员。

角色权限：

- 所有者：全部功能及管理员账号管理。
- 系统管理员：付款、成绩、题库和站点设置。
- 考官：查看成绩并复核。
- 财务：查看付款并人工确认。

### 主观题 AI 评分

正式环境通过服务器环境变量配置，不要将密钥写入代码或 Git：

```text
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_TIMEOUT_MS=20000
```

交卷时，系统只向模型发送主观题题干、考生答案、打分标准和本题满分，不发送考生姓名或东东数字ID。模型必须按打分标准逐题返回结构化分数和打分原因。分数、原因、模型和评分时间会随成绩持久化。若 API 超时、不可用或返回格式异常，该题自动使用本地评分要点算法，不会阻塞交卷。考官可在完整答卷中查看评分方式和打分原因。

### 答题码

所有者和系统管理员可在后台“答题码”页面生成凭证，设置备注、有效期和最大使用次数，并查看使用者与关联考试资格。考生在报名页填写答题码后可直接开始考试，不调用支付接口。

“计入收款统计”默认不勾选。勾选后，兑换记录会按该考生本次应收考试费计入后台累计/今日收款，但不会发起真实支付；未勾选时金额为 0。

### 考生账号

考生不需要注册密码。考生填写：

- 姓名 / 入职昵称
- 东东数字ID
- 联系方式（选填）

东东数字ID用于累计考试次数、计算费用和关联通过证明。

### 页面入口

```text
考生端：http://localhost:3000/
管理员后台：http://localhost:3000/admin（不显示在公开页面导航中）
证明查询：http://localhost:3000/certificate
```

## 本地启动

```bash
ADMIN_PASSWORD='请换成强密码' node server.js
```

首次启动前需要 Node.js 20 或更高版本。项目没有 npm 依赖，不需要执行 `npm install`。

如果只想快速本地查看：

```bash
node server.js
```

此时管理员密码为 `admin123`。正式部署前必须修改。

## 收款流程

1. 考生按付款页展示的微信或支付宝收款码完成付款。
2. 考生填写报名信息，首次免费并直接进入考试；第二次 20 元，第三至六次每次 30 元。
3. 管理员或财务核对对应渠道到账记录后，在后台确认收款。
4. 未付款申请超过 30 分钟后自动取消，考生可重新发起。
5. 考生刷新付款状态，确认后进入考试。

考费由每位考生按个人考核次数支付，全部归考官。收款仍进入已配置的商户或收款码账户，由收款方向考官结算；系统不自动转账。免费资格不计入收款金额或已确认付款笔数。

### 收款码

付款页已内置微信和支付宝两张收款码，图片文件位于 `public/payment-wechat.jpg` 与 `public/payment-alipay.jpg`。静态收款码不会主动通知网站到账，管理员核对到账后仍需点击“确认收款”。

## 演示模式

需要跳过人工确认、直接测试完整流程时：

```bash
DEMO_AUTO_PAY=1 ADMIN_PASSWORD='test-password' node server.js
```

演示模式只适合本地测试，不应在正式环境使用。

演示模式测试流程：

1. 启动演示模式。
2. 打开考生端，填写任意测试姓名和测试编号。
3. 点击“确认报名”，首次免费并直接进入考试。
4. 第二次及后续考核在演示模式下自动确认付款。
5. 付费考核点击“进入考试”。

如果浏览器还停留在旧付款页面，刷新页面即可；当前版本会自动兼容演示模式下的旧待付款单。

## 更新 Word 题库

```bash
python3 scripts/import-word-bank.py '比比鸟电竞文考题库.docx' data/question-bank.json
```

导入器兼容旧版题库，也支持新版 Word 中的知识问答、实战情景、选择题、判断题和补充考核题。导入后应使用后台题库管理确认组卷数量。

## 数据与备份

- `data/question-bank.json`：已导入题库，包含评分答案，不纳入 Git；部署时必须通过安全渠道提供并定期备份。
- `data/state.json`：付款、考试、成绩与证明记录，首次启动后生成。
- `data/config.json`：后台设置，首次保存后生成。
- `data/admin-users.json`：管理员账号与密码哈希。
- `public/payment-wechat.jpg`、`public/payment-alipay.jpg`：考试付款页使用的微信和支付宝收款码。

正式部署时请定期备份 `data/`，并使用 HTTPS、强管理员密码和反向代理。

## 清空测试记录

开发测试产生的付款、考试成绩和证明记录保存在 `data/state.json`。停止服务后删除该文件，下一次启动会自动创建空数据：

```bash
rm -f data/state.json
```

Windows PowerShell：

```powershell
Remove-Item data/state.json
```

不要在正式环境删除这个文件，除非已经完成数据备份。

## 云服务器部署

建议使用 Node.js 20+、PM2 和 Nginx：

```bash
cd jlb-entry-exam
ADMIN_PASSWORD='强密码' pm2 start server.js --name jlb-exam
pm2 save
```

Nginx 将域名反向代理到 `127.0.0.1:3000`，并配置 HTTPS。正式环境请关闭演示模式，不要设置 `DEMO_AUTO_PAY=1`。

## 常见问题

### 点击“我已付款，刷新状态”没有反应

确认服务是最新版本，并刷新页面。按钮会显示“正在查询付款状态…”。正式模式下，管理员确认到账前状态不会变成“已确认”。

### 扫码后能付款，但网站没有自动放行

这是正常的：静态商户码没有网站回调。管理员核对收款记录后，需要在后台确认收款。要自动放行，需要额外接入微信支付或支付宝的商户 API、验签和异步通知。

### 修改 CSS 后页面还是旧样式

当前 HTML、CSS、JS 已设置禁止缓存，并给 CSS 增加版本号。仍未更新时使用浏览器强制刷新：

- macOS：`Command + Shift + R`
- Windows：`Ctrl + Shift + R`

### 如何更新题库

替换根目录 Word 文档后重新导入：

```bash
python3 scripts/import-word-bank.py '比比鸟电竞文考题库.docx' data/question-bank.json
```

导入后重启 Node.js 服务。

## 安全提醒

- 不要在正式环境使用默认 `admin / admin123`。
- 不要在正式环境开启 `DEMO_AUTO_PAY=1`。
- 不要把 `data/state.json`、`data/config.json` 暴露到公网。
- 正式环境使用 HTTPS，并限制管理员后台访问权限。
- 定期备份 `data/`，尤其是 `state.json`。
